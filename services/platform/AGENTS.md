# Go control plane

Read the repository engineering principles. This module is the production control plane, separate from disposable experiments. Keep domain rules independent of HTTP and UI assets. `internal/httpapi` maps generated contracts to application operations; never serialize database account rows or encrypted values. Every tenant operation must establish workspace membership and the full nested project/environment identity. Membership writes lock the workspace before reading permissions. Take that lock only through `InWorkspace*`, `Store.BeginWorkspaceWrite` or `Store.WorkspaceWriteTransaction`, once and with no transaction open, after establishing the caller; they queue outside the connection pool. Never contact a Git provider or GitHub with a transaction open: ask through `gitAnswers`, or return a `providerCall`, so the call runs with nothing held and the whole decision is made again under the lock. Specification rows are immutable; layout has a separate write path.

A migration that only adds tables, nullable or defaulted columns, indexes, or functions and triggers on its own new tables ends with `INSERT INTO schema_additive_migrations (version) VALUES (<its version>);`, and its Down deletes that row, so the previous release still starts on it; any other says `-- astilba: not additive: <reason>`. `db/migrate_test.go` checks the shape of the claim, not its meaning: an additive release also keeps nothing the previous release must obey, such as a revocation, only in its new tables or columns, and accepts the rows the previous release writes while rolled back, so it fills what it needs from existing rows in a job that runs again rather than in the migration. Use `pnpm generate` for OpenAPI/sqlc output. Never edit generated files. `make check-app` runs static checks and short tests; `make verify-app` needs an explicit disposable Docker socket and runs the database/browser gates. Keep tests focused on observable security, persistence and concurrency contracts. `internal/execution` owns server identities, plans and transactional River operations. `internal/deployment` owns the visual plan and its restricted Compose/Traefik rendering. `internal/agent` owns the host journal, probe and visual executors. Keep browser and agent authentication separate. Visual plans freeze images, secret references and observed state; secret values are hydrated only for the assigned deployment agent. Preserve ownership checks, retained data and verified ingress recovery. File-authoritative Compose uses the same execution boundary and keeps original bundles separate from runtime projections. Provider imports and build execution belong to P5.

Read [JSON encoding](../../docs/json-encoding.md) before changing how a value is encoded. Read with `encoding/json/v2`. Write anything hashed, stored, sent between Astilba processes or returned by the API through `internal/stablejson`; plain v2 output changes digests and what responses mean. The `jsonguard` analyzer checks this.
