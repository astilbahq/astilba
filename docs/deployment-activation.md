## Runtime security: blocked, not accepted

The workflow still pins Node **24.18.1** and resolves Wrangler **4.114.0** from the unchanged frozen root lock in all three deployment directories. The inspected local Node reports builtin Undici **7.29.0**, OpenSSL **3.5.7** and zlib **1.3.1-e00f703**. Wrangler's distributed `wrangler-dist/cli.js` contains its own compiled Undici **7.28.0**; a lockfile override does not replace this copy. These observations are not a scan of the future GitHub-hosted Linux installation.

The forward upload uses Wrangler's bundled HTTP client and Node TLS; direct version rollback uses Node `fetch`/TLS, rejects redirects, has bounded request timeouts, and performs no automatic retry or force fallback. Neither is a local-only invocation. The smoke processes use Node HTTP/TLS without provider credentials. The [OpenSSL advisory](https://openssl-library.org/news/secadv/20260929.txt) places 3.5.7 below the 3.5.9 CRLDP-memory fix; hostile-certificate handling cannot be dismissed for HTTPS clients. Undici's [September advisories](https://github.com/nodejs/undici/security/advisories) also include fixes newer than the two embedded copies. Optional cache, WebSocket and interceptor compositions are not automatically reachable through these fetch paths; absence of a demonstrated composition is not blanket clearance of either bundle.

`deploymentRuntimeSecurity` is a new, independently required false gate. Before accepting it, assess the actual forward CLI, direct rollback helper and runtime/native closure against current vendor advisories, corroborate fixes/backports and applicable call paths, and verify any separately reviewed remediation with the existing age gates, frozen installs and tests. Preserve earlier findings and exclusions, including zlib/native-library coverage limits; do not infer resolution from a clean npm lock scan. Node's [announced October security release](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) is not evidence that a future version fixes a particular issue. This PR changes no dependency/runtime pin, suppresses no advisory and accepts no security risk.
